Accept payments on your website

AccessPay gives your site an accessible, hosted checkout page. You don't build a card form, and card details never touch your server. Test mode only: no real money moves.

How it works

  1. Create a test account and enter your website address. You get API keys.
  2. Your "Pay" button sends the customer to an AccessPay checkout page.
  3. They pay there, including the bank's OTP step if needed.
  4. We send them back to your website, and notify your server with a signed webhook.
Why can't the price just be in my button's HTML? Anyone can edit a web page in their browser and change ₹299 to ₹1. The price must come from your dashboard (payment links) or your server (checkout sessions).

Option 1: Payment link (no code)

Best for a fixed product or a simple "Pay" button.

  1. In the dashboard, open Payment links and create a link with a product name and price.
  2. Optionally, set where customers go after paying (a page on your website).
  3. Copy the link and use it as your button's address:
<a href="https://accesspay.example/l/plink_…" class="buy-button">
  Buy now – ₹299
</a>

Each click opens a fresh checkout, so one link can be paid many times.

Option 2: Checkout session (a few lines of server code)

Best when the amount changes, like a shopping cart. Your server creates a session with your secret key, then redirects the customer to its url.

Node.js (Express)

app.post('/checkout', async (req, res) => {
  const order = await createOrderFromCart(req);   // your code: total in paise

  const response = await fetch('https://accesspay.example/v1/checkout/sessions', {
    method: 'POST',
    headers: {
      Authorization: `Bearer ${process.env.ACCESSPAY_SECRET_KEY}`,
      'Content-Type': 'application/json',
      'Idempotency-Key': `checkout-${order.id}`,     // safe to retry
    },
    body: JSON.stringify({
      name: `Order #${order.id}`,
      amount: order.totalPaise,                      // ₹299 = 29900
      currency: 'inr',
      success_url: 'https://myshop.com/thank-you',   // must be on your website
      cancel_url: 'https://myshop.com/cart',
    }),
  });
  const session = await response.json();
  res.redirect(303, session.url);
});

curl

curl https://accesspay.example/v1/checkout/sessions \
  -H "Authorization: Bearer sk_test_…" \
  -H "Content-Type: application/json" \
  -d '{"name":"Order #1042","amount":29900,"currency":"inr",
       "success_url":"https://myshop.com/thank-you"}'

After paying, the customer lands on success_url?session_id=cs_…. Don't treat that visit as proof of payment (anyone can type a URL). Confirm with a webhook, or fetch GET /v1/checkout/sessions/cs_… and check payment_status.

Sessions expire after 30 minutes.

Webhooks

Set a webhook URL in Developers. We POST events such as checkout.session.completed, payment_intent.succeeded and refund.created, and retry failed deliveries.

Every request has an AccessPay-Signature: t=…,v1=… header: an HMAC-SHA256 of "<t>.<raw body>" using your webhook signing secret. Always check it:

import crypto from 'node:crypto';

app.post('/webhooks/accesspay', express.raw({ type: 'application/json' }), (req, res) => {
  const header = req.get('AccessPay-Signature') ?? '';
  const { t, v1 } = Object.fromEntries(header.split(',').map((p) => p.split('=')));
  const expected = crypto.createHmac('sha256', process.env.ACCESSPAY_WEBHOOK_SECRET)
    .update(`${t}.${req.body}`).digest('hex');

  const fresh = Math.abs(Date.now() / 1000 - Number(t)) < 300;   // reject replays
  const valid = v1 && v1.length === expected.length &&
    crypto.timingSafeEqual(Buffer.from(v1), Buffer.from(expected));
  if (!fresh || !valid) return res.status(400).end();

  const event = JSON.parse(req.body);
  if (event.type === 'checkout.session.completed') {
    markOrderPaid(event.data.object.id);   // your code
  }
  res.json({ received: true });             // reply quickly with 2xx
});

API reference

Base URL: https://accesspay.example. Send Authorization: Bearer sk_test_…. Amounts are integers in paise.

Endpoints
EndpointWhat it does
POST /v1/checkout/sessionsCreate a hosted checkout. Body: name, amount, currency, success_url?, cancel_url?, capture_method?
GET /v1/checkout/sessions/:idCheck status (open/complete/expired) and payment_status (unpaid/authorized/paid)
POST /v1/payment_linksCreate a payment link. Body: name, amount, success_url?
GET /v1/payment_intentsList payments
POST /v1/payment_intents/:id/captureCapture an authorised payment (when capture_method is manual)
POST /v1/refundsRefund all or part of a payment. Body: payment_intent, amount?

Add an Idempotency-Key header to POSTs so retries can't create duplicates. Errors look like {"error": {"type", "code", "message", "param"}}.

Security notes

  • Keep your secret key on your server. If it leaks, create a new one in Developers; the old one stops working at once.
  • Customers are only redirected to pages on the website in your settings.
  • Webhook URLs must be public HTTPS addresses.
  • We never store card numbers or security codes.
